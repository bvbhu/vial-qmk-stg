# tl12blef103 调试接线说明（矩阵板 / STM32 开发板 / CH582 开发板）

> 目标：用「STM32 开发板 + CH582/CH591 桥 + 独立矩阵板」搭出台面验证环境，
> 先跑通**矩阵坐标**与**灯珠序号**的发现，再写正式 vial 固件。
>
> 协议基准：`wch-ble-bridge/uart_protocol.md`（上游 `LinKeyDream/qmk_firmware_wireless`）。

---

## 一、系统组成与信号流

```
   ┌──────────────┐   USB(仅调试/供电)   ┌─────────┐
   │  PC / 记事本  │◄────────────────────│ 主机 HID │
   └──────────────┘                      └─────────┘
                                              ▲ USB
   ┌────────────────────┐   UART 128000 8N1  ┌──────────────┐
   │ STM32F103 开发板    │◄──────────────────►│ CH582F/CH591R │
   │ (tl12blef103 固件)  │  PA2/PA3 ↔ PB4/PB7 │   桥模块      │
   └────────┬───────────┘                    └──────────────┘
            │ 矩阵扫描 (2 行 × 6 列)
            ▼
   ┌────────────────────┐
   │   独立矩阵板        │  另: WS2812 数据线 → 灯珠串
   └────────────────────┘
```

**关键点**：**矩阵扫描和灯珠控制都是 STM32 本地行为**，发现阶段**不需要 CH582 桥**。
桥只在「让 PC 看到按键/改键」时才需要。所以你可以先只接矩阵板 + STM32，把坐标测准。

## 二、STM32F103 开发板（Bluepill）引脚分配

固件 `keyboard.json` 里的定义（**必须与接线一致**）：

| 用途 | STM32 引脚 | 说明 |
|---|---|---|
| **矩阵 ROW0** | **PA9** | 行线（驱动，逐行拉低扫描） |
| **矩阵 ROW1** | **PB15** | 行线（驱动） |
| **矩阵 COL0** | **PB12** | 列线（读入，带上拉） |
| **矩阵 COL1** | **PB14** | 列线（读入） |
| **矩阵 COL2** | **PB5** | 列线（读入） |
| **矩阵 COL3** | **PA8** | 列线（读入） |
| **矩阵 COL4** | **PA10** | 列线（读入） |
| **矩阵 COL5** | **PB13** | 列线（读入） |
| **WS2812 数据** | **PB6** | 灯珠串数据（DIN） |
| **BHQ UART TX** | **PA2** | → 桥的 PB4 (RX) |
| **BHQ UART RX** | **PA3** | ← 桥的 PB7 (TX) |
| 电池分压 | PA7 | BAT+ --100K-- PA7 --100K-- GND（发现阶段可不接） |
| USB 电源检测 | PA6 | 5V --100K-- PA6 --100K-- GND（发现阶段可不接） |

**不可用的引脚**（已被占用，别拿去接矩阵）：
`PA11/PA12`（USB D-/D+）、`PA13/PA14`（SWD 调试）、`PD0/PD1`（晶振/低功耗）、`PA2/PA3`（BHQ 串口）。

> ⚠️ **注意区分 PA9/PA10 与 PA11/PA12**：PA9/PA10 本固件用作 COL3/COL4，
> 它们同时也是 USART1 的 TX/RX，但本固件不用 USART1，可安全当普通 GPIO。
> 不要接到 USB 的 D+/D-（那是 PA11/PA12，接了会干扰 USB 枚举）。

## 三、CH582F / CH591R 桥模块

桥侧代码：`wch-ble-bridge/`，两块板共享 `ble_bridge_app/{APP,Profile}`。

| 桥引脚 | 接到 |
|---|---|
| **PB4 (UART0 RX)** | STM32 **PA2**（TX） |
| **PB7 (UART0 TX)** | STM32 **PA3**（RX） |
| **GND** | STM32 **GND**（必须共地） |
| 3V3 / VCC | 按模块要求供电（3.3V 电平两侧一致） |

**交叉接线**：TX→RX、RX→TX。接成 TX→TX 是最常见的错误，表现为完全无响应。

波特率固定 **128000 8N1**，两侧都由固件配置，无需外部设置。

> 桥模块的固件需要单独烧录（WCH 工具链 + MounRiver Studio 工程在 `ch582f_ble_bridge/`、
> `ch591r_ble_bridge/`）。本说明只涉及 STM32 侧固件。

## 四、独立矩阵板接线

### 4.1 二极管方向（COL2ROW）

本固件用 `"diode_direction": "COL2ROW"`：

```
   ROW ──►|── COL          二极管：阳极接 ROW，阴极接 COL
                           电流从 ROW 流向 COL
```

- **ROW** = 驱动端（固件逐行拉低扫描）
- **COL** = 读入端（固件读电平判断哪个键按下，带上拉）

**接反的后果**：整行/整列恒触发或完全不触发。若发现某个键「永远按下」或「永远不响应」，
优先怀疑二极管方向。

### 4.2 按键矩阵连线

每个按键放在「行线 × 列线」的交叉点上：

```
             COL0   COL1   COL2   COL3   COL4   COL5
              │      │      │      │      │      │
   ROW0 ──────┤K──────┤K──────┤K──────┤K──────┤K──────┤K
              │      │      │      │      │      │
   ROW1 ──────┤K──────┤K──────┤K──────┤K──────┤K──────┤K
```

每个 `K` = 一个按键 + 一个二极管（阳极朝列）。

**这是「矩阵坐标」的物理含义**：某键接在 ROW1/COL3 上，它的坐标就是 `(1,3)`。
固件扫描时读到的就是这对数字，与外壳上的丝印无关——**这正是发现固件要告诉你的东西**。

### 4.3 最小接线（只测矩阵，不接灯）

若暂时不想接灯珠，只接：

```
STM32 PA9  → 矩阵 ROW0
STM32 PB15 → 矩阵 ROW1
STM32 PB12 → 矩阵 COL0
STM32 PB14 → 矩阵 COL1
STM32 PB5  → 矩阵 COL2
STM32 PA8  → 矩阵 COL3
STM32 PA10 → 矩阵 COL4
STM32 PB13 → 矩阵 COL5
STM32 GND  → 矩阵 GND（如果矩阵板有独立供电/参考）
```

灯珠不接时，RGB 相关代码照常运行但看不到效果，**不影响矩阵坐标发现**。

## 五、WS2812 灯珠串接线

| 灯珠串引脚 | 接到 |
|---|---|
| **DIN**（数据输入） | STM32 **PB6** |
| **5V / VCC** | 5V（注意：WS2812 通常 5V 供电，**数据线电平需 ≥0.7×VDD ≈ 3.5V**） |
| **GND** | 与 STM32 共地 |

### 5.1 电平问题（重要）

STM32 输出 3.3V，WS2812 在 5V 供电时要求数据高电平 ≥ 0.7×VDD = 3.5V。
3.3V 常常「临界可用」但不保证。三种常见处理：

1. **灯珠也 3.3V 供电**（多数 WS2812B 在 3.3V 可点亮，亮度略降）——最简单；
2. 串一个 **74HCT245 / 74AHCT1G125** 做 3.3V→5V 电平转换；
3. 数据线串一个 **1N4148 二极管到灯珠 VDD**（抬高低电平参考），属低成本偏方，
   可靠性一般，仅调试可用。

**发现阶段建议**：先用 3.3V 供电验证灯珠序号，确认无误后再按实际板子改。

### 5.2 灯珠序号的意义

WS2812 是**串联移位**的：数据从 DIN 进，经过第 0 颗，再流向第 1 颗……
所以「第 N 号灯珠」= **从 DIN 端数起的第 N 颗**。

固件里的 `index` 就是这个序号。发现固件让你逐颗点亮，就是要你确认：
**「第 3 号灯珠」在物理上位于哪个键下方**——这是写 `rgb_matrix.layout` 的依据。

## 六、接线检查清单

上电前逐项确认：

- [ ] STM32 **PA2 → 桥 PB4**，**PA3 → 桥 PB7**（交叉，不是直连）
- [ ] STM32 与桥 **共地**
- [ ] 矩阵列线接 **PB12/PB14/PB5/PA8/PA10/PB13**，行线接 **PA9/PB15**
- [ ] 二极管方向：**阳极朝 COL**
- [ ] 灯珠 DIN 接 **PB6**，灯珠与 STM32 **共地**
- [ ] 没有把任何矩阵线接到 `PA11/PA12/PA13/PA14`
- [ ] STM32 用 **USB 供电**（开发板自带 USB 口），不要同时从别处灌 5V

## 七、固件烧录

编译产物：`vial-qmk-stg/bvbhu_tl12blef103_default.bin`

### 7.1 进入 bootloader

Bluepill + `stm32duino` 引导：

1. 将 **BOOT0 跳线置 1**（BOOT0→3.3V），**BOOT1 置 0**；
2. 按一下 **RESET**；
3. 此时进入 bootloader。

> 部分 Bluepill 板出厂已烧 stm32duino bootloader；若没有，需要先用 ST-Link
> 通过 SWD 烧一次 bootloader，或用 `stm32duino` 的串口下载方式。

### 7.2 用 ST-Link 烧录（推荐，免 bootloader 折腾）

```
STM32 SWD:  SWDIO=PA13, SWCLK=PA14, GND, 3V3
工具:       STM32CubeProgrammer / st-flash / openocd
```

烧录后把 **BOOT0 跳回 0**，复位运行。

### 7.3 验证是否跑起来

上电后如果 RGB 全灭（矩阵发现模式默认全灭、只在按键时闪绿），说明固件在跑。
详见 `BLUETOOTH.md` 的配对操作步骤。
